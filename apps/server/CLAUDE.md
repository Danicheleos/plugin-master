# CLAUDE.md (apps/server)

Server implementation notes, moved out of the root CLAUDE.md. Web-side details of the same features are in `apps/web/CLAUDE.md` (the evals, chat, plans and git web parts below are described inline where they were written); shared schemas are in `libs/protocol/CLAUDE.md`.

- `apps/server`: Fastify 5. `src/{main,app,config}.ts`, `lib/errors.ts` (`AppError`), `security/guard.ts` (Host/Origin/token hook + `verifyWsRequest`), `spaces/{registry,scaffold,templates,service,routes}.ts`, `files/{safe-path,service,watcher,routes,browse}.ts` (`browse.ts`: `GET /api/fs/browse?path=<abs>` lists subdirectories for the web folder picker, default `config.userHome ?? os.homedir()`; all space paths go through `resolveInSpace`, which checks the lexical path and the realpath of the deepest existing ancestor, so symlinks cannot escape the space and NUL bytes are rejected; the service functions take a space root, routes look it up in the registry), `claude/{session,session-manager,permissions,map-events,history,routes}.ts` (see Chat below), `lib/async-queue.ts`, `lib/text.ts` (`cut`), `ws/hub.ts` (`createHub(config)`: `plugin`, `broadcast`, `on(type, handler)`, `onSubscribe`, `onIdle`). `buildApp(config)` is what tests use with `app.inject()`. Tests are `*.test.ts` next to the code.
- WebSocket: `@fastify/websocket` must be registered on the root app **before** `registerGuard` (see `app.ts`); otherwise an upgrade rejected by the guard leaves its socket open and `app.close()` hangs. `/ws` is gated by a route-level `onRequest` hook calling `verifyWsRequest` (Fastify matches the decoded route, so `/%77s` cannot bypass it). Watching is scoped (a recursive watch over a big plugin hit EMFILE and the unhandled chokidar `error` killed the server): the client sends `fs.watch {spaceId, paths}` (full set: root `''`, expanded dirs, open file; only after `subscribe`, replayed after it on reconnect), `files/watcher.ts` keeps per-client sets and watches their union per space with one chokidar v4 watcher (`depth: 0`, `.plugin-master` always), changes serialized through a queue; growing uses `add`, shrinking recreates the watcher (chokidar's `unwatch` keeps the path ignored); `hub.onLeave` (unsubscribe/socket close) drops a client's set; watcher errors only go to `app.log.error`. The tree is lazy: `GET /api/spaces/:id/tree?dir=<rel>` returns one level, web `useDir` keyed `['tree', id, dir]`, `FileTree` loads a dir when expanded; `WorkspacePage` renders `<Workspace key={id}>` so state resets per space; `NewFileDialog` offers only already loaded dirs. `main.ts` strips the query string from logged request URLs because `/ws` carries the token there.
- Chat (iteration 5): `session-manager.ts` keeps per-space `{session, status, events}` in memory only and registers the hub handlers (`chat.send/interrupt/reset`, `permission.reply`, `onSubscribe` sends `chat.history` plus still-pending `permission.request`s). `session.ts` wraps the SDK `query()` in streaming-input mode (`AsyncQueue<SDKUserMessage>`, preset `claude_code` system prompt with `append`, `settingSources: ['project']`; constants and the options builder `sessionQueryOptions` at the top of `session.ts`: model `claude-opus-5-5`, and `env` = `process.env` merged with `CLAUDE_CODE_AUTO_COMPACT_WINDOW=300000` (the CLI's auto-compact window, as `/autocompact`; the env var wins over the `autoCompactWindow` setting) plus `CLAUDE_CODE_SUBAGENT_MODEL=claude-sonnet-5-5` and `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` (the CLI then ignores the Agent tool's `model` input and agent-definition models), because the SDK `env` option replaces the inherited env); the master itself does not run shell/web tools and is asked to delegate anything beyond reading and small edits: `claude/master-hook.ts` `MASTER_HOOKS` (`PreToolUse` hook in `sessionQueryOptions`, so it holds in every permission mode) is an allow-list (`MASTER_ALLOWED_TOOLS`: Read/Glob/Grep/Edit/Write, Agent/Task*, TodoWrite, ToolSearch, AskUserQuestion, Enter/ExitPlanMode, Skill, SendMessage, plus `mcp__plan__*`/`mcp__evals__*`): every other tool of the master (shell, web, notebooks, MCP resources and `.mcp.json` tools) is denied with a "delegate to a subagent" reason unless the hook input has `agent_id` (set only for calls made inside a subagent); `mcp__evals__eval_run` returns `ask` for the master and subagents alike (always prompts, also in auto/dontAsk); the default prompt (`DEFAULT_MASTER_PROMPT`, copied to the user-editable `.plugin-master/MASTER.md` on the first session; a pinned copy is not added twice) tells it to plan, delegate with complete briefs and review short reports; the manager takes a `SessionFactory` so tests use a fake. Context (iteration 6): `context/build-context.ts` `buildContext(root, files)` reads each file via `resolveInSpace` (missing = skipped, order kept; outside-space path, directory or NUL-containing file throws, so the chat gets an error instead of a session with partial context) and returns `{ text, missing }` (`</file>` in content and `"` in paths are escaped). `getConfig` returns `masterContext: []` when `config.json` is missing; `setConfig` (PUT) rejects entries outside the space (400). `createSession` wraps any config/context error as `CONTEXT_INVALID` naming `config.json` and the entry. It passes `text` as `appendSystemPrompt` and stores the requested `masterContext` as `state.contextFiles` plus `missing` as `state.missingContext`; `contextFiles` is `null` when no session exists (cleared on drop/reset/SDK error). Status goes idle only when `state.turns` (sent turns awaiting their result) is empty. It applies only when a session is created (first `chat.send` after start/reset/SDK error): it is fixed for the session's life (prompt cache), config edits need "New session". `chat.history`/`chat.status` carry `contextFiles: string[] | null` and `missingContext`. Web `features/context/`: `useSpaceConfig`/`useSetSpaceConfig` (`['config', id]`, invalidated by `fs.changed` of `config.json` in `WorkspacePage`), `ContextToggle` (📌 in `FileTree`), `ContextSummary` (chat header; the "Context changed" banner shows when `contextFiles` is non-null and differs from the config; every entry has an Unpin button; `useToggleContext` is optimistic). `map-events.ts` (`mapSdkMessage`) is the only code that knows SDK message shapes; its fixtures in `claude/__fixtures__/` are real captured messages. Tool permissions go through `canUseTool` -> `permission.request` -> `permission.reply` (no timeout, no remembering; an aborted signal from interrupt/reset drops the request); allow returns `updatedInput: input`, deny returns `Denied by user`. Callbacks of a replaced session are ignored (`state.session !== session`). After an SDK error the session is dropped and the next `chat.send` creates a new one. An interrupted turn still ends with a `result` event (and a status `idle`).
- Auto-commit (`claude/auto-commit.ts`, wired in `session-manager.ts`): needs features `git` AND `autoCommit` (checked when the turn is sent and again at commit) and a repo, else silently nothing. `chat.send` is dispatched through a per-space chain: it takes a `git status` snapshot (`snapshot`: XY code plus a sha1 of each dirty path's working-tree content, symlinks hashed by target text, files > 8 MB by size:mtime, 16 read at once; at commit only paths with an unchanged XY code are re-hashed), queues `{prompt, before}` in `state.turns` and then sends; each `result` shifts the oldest turn and `commitTurn` commits (selective `gitCommit`, under the repo lock) only paths absent from the start snapshot, with another XY status or with another content hash. Paths already dirty before the turn and unchanged stay uncommitted (the user's own work); a file the agent edits further is committed whole, including the user's earlier uncommitted edits in it; overlapping queued turns can fold into the earlier commit. Nothing changed = no event. All of `.plugin-master/` is excluded (runs are written every turn; plans/config are app state also edited from the UI). Message `agent: <first non-empty prompt line, ≤60 chars>` + blank line + `Run: <sessionId>`. Interrupted turns end with a `result`, so their changes are committed too. Result: chat event `commit {hash, files, message}` (dimmed line in `MessageList`) plus `git.changed` (also when the conversation was reset meanwhile; only the chat event is dropped then); any failure becomes a chat `error` event (`Auto-commit failed: …`); reset/error drop the queue. A staged rename commits both paths (snapshot entries carry `from`); more than 200 changed paths are not committed (error event `Auto-commit skipped: N changed files, commit manually`); snapshots use `git --no-optional-locks status`. Known limits: user edits to clean files during a turn are committed as the agent's; with queued turns a commit can include the next turn's early edits; a turn ending in an SDK error is not auto-committed.
- Experiments (stages): `experiments/stages.ts` `runStage({role, cwd, spaceRoot, prompt, schema, recorder, signal, onPermission, ...})` runs one one-shot SDK `query()` (injectable `queryFn`, `outputFormat` json_schema from `z.toJSONSchema`, result from `structured_output` re-validated with zod; failures are `StageError` `ABORTED`/`SDK_ERROR`/`INVALID_OUTPUT`) and records it as a run of `spaceRoot` (run id = returned `sessionId`). `stagePolicy` is the `canUseTool`: master/analyst read-only (reads only inside cwd + `additionalDirectories`, rest denied "read-only stage"); executor edits only inside the worktree via `resolveInSpace` and outside `.git`/`.plugin-master` (case-insensitive and same-inode checks), the allowed input carries the checked absolute path (no `~` expansion by the tool); edits matching `NEEDS_APPROVAL` (`hooks/`, `scripts/`, `bin/`, `evals/`, `.claude/`, `.claude-plugin/` segments, `.mcp.json`/`.lsp.json`, script extensions; the eval runs the worktree with `--trust-plugin`) and other tools go to `onPermission` (default deny). `settingSources: []`, `permissionMode: default`, `Task`/`Agent` disallowed for every role, `maxBudgetUsd` per stage; a failed result's cost rides on `StageError.costUsd`. Prompts in `experiments/prompts.ts`, result schemas in `/protocol` `lib/experiments.ts`.
- Hooks (server): `hooks/{service,routes}.ts` serve `GET/PUT /api/spaces/:id/hooks` over `plugin` (`hooks/hooks.json` plus string/array paths in `.claude-plugin/plugin.json` `hooks`; inline objects are not editable), `project`/`local` (`.claude/settings[.local].json`), `skill` (`skills/*/SKILL.md`) and `agent` (`agents/*.md`, frontmatter `hooks:`) files, all via `resolveInSpace`, max 200 skill/agent files each; a broken file is a source row with `error`, PUT validates with `validateGroup` (422, messages joined by newline), rejects files outside the discovered set (400), refuses to overwrite a broken file (422) and writes atomically under `withLock` per file. Frontmatter is edited through the `yaml` Document (comments, other keys and the body are kept; long lines are not folded, flow-collection spacing may normalize); JSON keeps the existing indent and trailing newline, and `hooks` moves to the end of the object when rewritten.
- Experiments (core, feature `masterLoop`, needs git; git off turns `autoCommit` and `masterLoop` off in `setFeatures` and the web menu): `experiments/{store,worktree,routes}.ts`, schema in `@pm/protocol` `lib/experiments.ts`. Record `.plugin-master/experiments/<n>.json` (n = max + 1, atomic write under `lockedExp`), branch `exp/<n>`, worktree `<PM_HOME>/worktrees/<spaceId>/exp-<n>` made from the space's HEAD (409 `NOT_A_REPO`/`NO_COMMITS`). `diff` = committed + uncommitted + untracked files vs `base` (reuses `gitDiff(root, path, ref)`, 200 files max). `merge` needs no tracked changes in the main tree outside `.plugin-master/` (`GIT_DIRTY`; untracked files such as eval results are ignored), commits the worktree first, `merge --no-ff`, aborts on conflict (`GIT_CONFLICT` with the files; an untracked main file the merge would overwrite is also `GIT_CONFLICT`, naming it, with nothing changed), then removes worktree and branch. `discard` removes both. Every worktree path from a record is checked with realpath against the worktrees dir before git removes it (400 `EXPERIMENT_PATH`). Routes `…/experiments[/:n[/diff|merge|discard]]` broadcast `experiments.changed`. No agent sessions yet.
- Experiments (loop): `experiments/loop.ts` `createExperimentLoop({evalRunner, permissions, recorder, onChange, onError, queryFn?})`, wired in `app.ts`. `POST …/experiments/run {maxCostUsd (0,20], focus?, cases?}` (needs `evalTrusted`, else 409 `EVAL_UNTRUSTED`; one per space in memory, 409 `EXPERIMENT_RUNNING`, 409 `EVAL_RUNNING` while any eval runs) creates the experiment, returns the `running` record and runs in the background: hypothesis (master in the space, prompt = focus + `summary.ts` `summarizeEval` of the newest eval group covering `cases`) -> execute (executor in the worktree, then commit `exp/<n>: <title>`; no changes = failed; any changed `.md` whose frontmatter `hooks` differ from `base` (`newHooks`, `splitFrontmatter` from `hooks/service.ts`) needs one permission prompt `Experiment <n>: run eval with new hooks in …` before the eval, because it runs with `--trust-plugin`; deny = failed `eval not approved: new hooks in …`, no eval) -> eval (`evalRunner.start(spaceId, root, req, target = worktree)`: trust from the space, results/out dir and cwd from the worktree; the loop writes a self-ignoring `<evalDir>/results/.gitignore` (`*`) in the worktree so results never reach a merge; every SDK stage gets `maxBudgetUsd` = what is left of `maxCostUsd` (<= 0 = failed before the stage); the eval gets the rest minus a 10% analyst reserve; a failed stage keeps its reported cost; baseline = newest main eval covering the requested cases, else `comparison.baseline: null`, no second eval) -> analyze (analyst in the worktree, failed-case trace excerpts) -> `ready` with `stateProposal`. Every stage is persisted on the record (`stage`, `stages[stage] {runId,startedAt,endedAt,costUsd,error}`, `plan`, `execution`, `files`, `comparison`, `analysis`, `costUsd`) and broadcast as `experiments.changed`; any error = `failed` with the message, worktree kept. `POST …/:n/cancel` aborts the stage (AbortSignal; the eval runner's SIGINT for the eval stage), record `failed` "cancelled". Executor permissions: `onPermission` -> the chat's shared `createPermissions` (`chat.permissions`, one `permission.reply` handler) with requestId `exp-<n>-<uuid>` and toolName `Experiment <n> executor: <tool>`; pending ones are re-sent on subscribe like chat ones. Merge/discard of the running experiment (in-memory slot) = 409; `POST …/evals/run` is 409 `EXPERIMENT_RUNNING` while the space has one (`loop.busy`); GET list/one `loop.settle` a `running` record not in the slot (left by a crash) and persist it as `failed` "interrupted (server restarted)"; `/run` broadcasts only via the loop's `onChange`; after a successful merge `proposal.ts` `writeMergeNotes` appends the proposal to `.plugin-master/STATE.md` and an entry to `DECISIONS.md` (only loop records have `stateProposal`). Runs recorded under the space root, run id = stage `runId`.
- Sessions: the SDK stores transcripts per cwd in `~/.claude/projects/`. `claude/history.ts` (`History`: `list(dir)` via `listSessions`, `events(dir, id)` via `getSessionMessages` + `mapSessionMessage`, which skips subagent messages) is injected into `buildApp(config, logger, history)` so tests fake it; `GET /api/spaces/:id/sessions` lists them for the space root. State has `sessionId` (captured from live SDK messages, sent in `chat.history`/`chat.status`). `chat.resume {spaceId, sessionId}` and `chat.reset` share `replaceConversation` (bumps `generation`, drops the live session); the next `chat.send` creates the SDK session with `resume: state.sessionId`. Reset sets it to null; an SDK error keeps it. Stored transcripts have no `result` events (no past costs). Web: session `Select` in `ChatPanel` (`useSessions`, keyed by sessionId+status, `keepPreviousData`).
- Run store: `runs/recorder.ts` `createRecorder(onError, head)` (injected into `createSessionManager`) appends every raw SDK message of a session, plus a synthetic `user` line per `chat.send` (the SDK does not echo prompts), to `.plugin-master/runs/<sessionId>/messages.jsonl` and keeps `meta.json` (`RunMeta` in `@pm/protocol` `lib/runs.ts`: title, start/end, turns, cost, models, `claudeVersion` from the init message, git `commit`, `resumedFrom`). Lines are buffered until the first message carries `session_id`; the run id is the id of the session that produced the messages (resume with the same id appends, a new id starts a run with `resumedFrom`); writes are serialized per run dir (`withLock`), append-only, and errors are only logged. `GET /api/spaces/:id/runs` (newest activity first, cap 200, broken meta = `{id, error}`) and `GET …/runs/:runId/trace` (`parseTrace` of messages.jsonl, `RUN_NOT_FOUND` 404, strict id regex) are in `runs/{service,routes}.ts`.
- Features: optional, all off by default, `features {git, autoCommit}` in `config.json` (`FeaturesSchema` in `@pm/protocol` `lib/rest.ts`; missing = false, unknown keys dropped; `FeaturesInputSchema` is a plain partial because `FeaturesSchema.partial()` would reset omitted keys through the defaults). `features/{service,routes}.ts`: `GET/PUT /api/spaces/:id/features` (partial update under `withLock`; `autoCommit` without `git` = 400) and `requireFeature(root, name)` (409 `FEATURE_DISABLED`) for gated routes and WS handlers; a PUT broadcasts `features.changed {spaceId, features}`. `PUT /config` still takes only `masterContext`. - Git (gated by `git`): `git/{service,routes}.ts` on `simple-git` (system git, cwd = space root; plain response types in `@pm/protocol` `lib/git.ts`). `GET …/git/{status,diff?path=,log?limit=,branches}`, `POST …/git/{init,commit,branch,switch}`. Repo = `.git` exists in the space root (not an ancestor); status of a non-repo is `{isRepo:false}`, other routes 409 `NOT_A_REPO`. Diff: `old` from `HEAD:<rel>`, `new` from the working tree, `binary` (NUL) / `tooLarge` (> 1 MB) have empty texts. Commit stages `add -A` (all or the given paths) and commits only those (`commit -- paths`); nothing staged = 409 `NOTHING_TO_COMMIT`. Branch names must match a strict regex (no leading `-`) and `git check-ref-format --branch`; switch refuses a dirty tree with 409 `GIT_DIRTY` unless `carry`, which only runs `git switch` (git carries the changes or fails with 409 `GIT_ERROR`; nothing is discarded). Git errors become 409 `GIT_ERROR`; a non-zero git exit is an error even with empty stderr (simple-git `errors` option, e.g. a silent `exit 1` hook). All calls run with the top-level `--literal-pathspecs` (a file named `[ab].md` is not a glob; passed via simple-git `binary: ['git', flag]`, not `.env()`, which throws when `GIT_EDITOR` is set); `GitFile.from` is the old path of a staged rename and the web selection commits both. The log of a repo without commits is `[]`. Calls are serialized per repo (`withLock` with its own key). commit/branch/switch/init broadcast `git.changed {spaceId}`. Tests set `GIT_CONFIG_GLOBAL=/dev/null` and author env vars. Selective commits never stage or commit unrelated files (`add -A -- paths` + `commit -- paths`; already staged unrelated files stay staged). Web `features/git/` is the `git` widget (`WIDGET_FEATURE`, not in the default layout): `GitWidget` (not a repo = Initialize button), `BranchBar` (switch, dirty tree = confirm modal with `carry`; new branch), `StatusList` (checkbox per file, all checked by default; click opens `DiffPane`, Monaco DiffEditor HEAD vs working tree), `CommitForm` (+ collapsed `Log`); queries `['git', id, …]` are invalidated on `git.changed` and when the chat turn goes idle; `fs.changed` refetches only status and the open diff, debounced 300 ms.

Web `features/plans/` (`PlanPanel` at the top of `ChatPanel`, `NewPlanDialog` activates the new plan before asking the agent to draft phases, `AgentStats`: the master `ContextMeter` and the active plan's progress row sit at the top of the plan widget, outside its Collapse; `stats.tasks` is not rendered).
- Description optimizer (experiment `kind: 'description'`, p17 A): `POST …/experiments/run {kind: 'description', skill, maxCostUsd, iterations 1..5 (3)}` (same preconditions as the loop; `prepareDescription` in `experiments/description.ts` fails before anything is created: 404 `SKILL_NOT_FOUND`, 400 `NO_TRIGGER_CASES`). Trigger cases = suite cases tagged `trigger`, `holdout`-tagged ones are the holdout (protocol `splitTriggerCases`); no holdout = allowed, verdict `unknown` + warning. `descriptionBody` (shares `experiments/kit.ts` `stageKit`/`evalOn`/`commitWorktree` with the master loop; stages `propose`/`eval`, `stages` shows the current iteration, the money of finished iterations is banked in `candidates[].costUsd`): baseline eval of the original (candidate 0), then per iteration a read-only `master` stage (cwd = the skill dir in the worktree, so holdout cases and `evals/` are unreadable; prompt = skill, current/tried descriptions, TRAIN cases' scores and failed-grader explanations only; `DESCRIPTION_STAGE` via `StageParams.systemPrompt`), gates (non-empty, <= 1024 chars, no control chars/line separators, not a repeat; a rejected one is reported to the next proposal and costs an iteration), `setDescription` (protocol, lossless, rewrites only the description line), commit `exp/<n>: description iteration k` (any file other than that SKILL.md = failed), eval of train+holdout cases with 3 runs. The cost cap ends the loop gracefully (warning); other errors fail the record. At the end the best candidate (best train, ties shorter, original wins ties) is written/committed so the worktree HEAD is what merge takes; verdict `pass` = best holdout >= original's, bestIndex 0 = `fail` (nothing beat the original). `evalOn` keeps only its own invocations of the result group (evals in one worktree within 10 minutes would otherwise merge). Merge/discard/cancel are the existing routes; `writeMergeNotes` adds the description to DECISIONS.md.

- Eval runner (E2): `evals/runner.ts` `createEvalRunner(hub, spawner)` spawns `claude plugin eval <root> --json <out>/aggregate-result.json --output-dir <out> --no-publish --max-cost-usd N [filters] [--trust-plugin]` (`shell: false`, `stdio: ['ignore','pipe','pipe']`, inherited env; target before options; string values starting with `-` rejected by the schema). `--trust-plugin` only with `evalTrusted: true` in `config.json` (else 409 `EVAL_UNTRUSTED`; `PUT …/evals/trust`). One run per space (409 `EVAL_RUNNING`); WS `eval.output`/`eval.status`, last 500 lines replayed as `eval.history` on subscribe; `POST …/evals/cancel` = SIGINT; exit 0 done, 1/2 done if the aggregate exists, 130/cancel cancelled; `close()` SIGTERMs children. Tests use a fake spawner; never run real evals in tests. `--ablation none` unless the form's baseline checkbox is ticked (`with-without`, ~2x cost; the CLI's own default would be with-without). The CLI prints its output only near the end. Grouping (`evals/groups.ts`): the runs list returns groups of consecutive invocations (10 min gap vs the group's latest end, same model/ablation/Claude/plugin version), because harnesses often run one case per invocation; `GET …/evals/groups/*` (any member run id) returns a merged result (latest per case, `cases[].runId`).
- Eval E3/E4: `evals/suite.ts` (`GET …/evals/suite`: cases and tags from `prompt.md` frontmatter / `case.yaml`, `yaml` dep) feeds the run form dropdowns; `cases[]` runs one invocation per case sequentially under one lock (the CLI's `--case` takes no brace globs; outputs `results/<id>`, `<id>-2`, …; cost limit split evenly). "Build eval suite with agent" sends `BUILD_SUITE_PROMPT` to the chat; `MASTER_PROMPT` has a compact case-format reference. Runs use `--keep-temp`; `evals/traces.ts` copies each run's `tracePath` to `<out>/traces/<arm>/<case>-<n>.jsonl` and deletes the kept sandbox (`e-*` directly under realpath of `tmpdir()` or `/tmp` — on macOS the CLI uses `/private/tmp` —, lstat-checked, chmod'ed first because the CLI seals it; also the `⚠ kept <path>:` lines). Trace lookup also reads the ambicode harness layout `<results>/traces/<any>/<aggregate startedAt key>/<case>-<n>.jsonl`; top-level `results/*.json` aggregates (e.g. `bare.json`) are runs too. `evals/trace.ts` parses stream-json traces into `{metrics, turns}` (model calls = distinct `message.id`, context = input + cache read + cache creation); metrics cached by mtime. `GET …/evals/runs/<id>/trace?case=&arm=&n=`. Web: metrics columns, `TraceView`, `EvalCompare` (ablation arm or any other group as baseline). Server-attached trace metrics on arm runs are `traceMetrics` (the ambicode harness writes its own `metrics` there). `TraceModal` has a Flow | Log switch: Flow = `TraceFlow` (block scheme: prompt (`Trace.prompt`, first user text), turns, tool branches coloured by `toolKind`, `describeTool` one-line summaries, subagents as nested lanes, runs of >4 same-kind calls collapsed), Log = the flat `Turns` list; runs without `traceMetrics` show "no trace".
- Eval progress and agent eval tools: a run without `cases` is expanded by the runner to the parsable suite cases (narrowed by `tags`, any; skipped when a name has glob chars or none/no suite), one invocation each (cost split evenly, dirs `<id>`, `<id>-2`, ...). `EvalStatus.progress {total, done, current, cases[{name, state queued|running|done|failed|cancelled, score?}]}` (score = `aggregates.overallScore` of that invocation's aggregate) rides on every `eval.status`/`eval.history`; each case change is an extra `running` status. Web `EvalProgressView` (bar "N of M cases" + case list) in `EvalRunPanel`; "Build eval suite with agent" opens `BuildSuiteDialog` (Cancel focused, Send to agent). `evals/tools.ts`: in-process MCP server `evals` (`eval_run {cases,tags,runs,model,maxCostUsd}` -> `runner.start`, returns the run id; `eval_status` -> status/progress and summed cost), passed per session by `createSessionManager`'s 6th arg `{runner, busy}`. Only `eval_status` is in `allowedTools`; `eval_run` goes through `canUseTool` (user prompt shows maxCostUsd). Trust, `EVAL_RUNNING` and `EXPERIMENT_RUNNING` errors come back as tool errors; `MASTER_PROMPT` says to use these tools, not Bash.
- Eval suites view (default in the Evals tab; "Invocations" = the old group list): `evals/suites.ts` `buildSuites` (pure) behind `GET …/evals/suites`. Suite key = `plugins[0].name` + eval-dir prefix of the case dirs; `main` = plugin name equals the space's `plugin.json` name, `baseline` = another suite sharing case names. Inside a case, runs are sectioned by auto baseline: own ablation `without` arm, else the latest baseline-suite run of that case with the same model at or before it, else the nearest later one (`after: true`). Runs duplicated by `startedAt` + suite (e.g. `results/plugin.json` copy) count once; runs without cases are skipped. Web `EvalSuitesList` → `EvalRunView focusCase` / `EvalCompare initialBaseline`.
- Eval targets ("Skills & agents" toggle in the Evals tab): `evals/targets.ts` behind `GET …/evals/targets`. `mapCases` (pure) maps each suite case (`readSuite` now also exposes `toolGraders` from `case.yaml` and `graders/*.md`) to plugin skills/agents: (a) `tool_used` graders with tool `Skill` (skill) or `Agent`/`Task` (agent) whose `input_match` is a plain name (`nameInMatch`; alternations/classes ignored; the name must exist in `skills/`/`agents/`), (b) tags `skill:<n>`/`agent:<n>` (no existence check), (c) only if none: longest existing name equal to or prefixing (`-_./ `) the case name or dir name; else `unmapped`. A case can have several targets. `aggregateRuns` merges the cases' per-run rows (main suites) per run id: mean per metric over the cases present in that run, `maxContext` = max, baseline metrics aggregated the same way; `contextBytes` = `versions/logic.ts#contextBytes` of SKILL.md / agent file (frontmatter description + body bytes, the same number as the versions gate `skillContext`; references not counted). Web `EvalTargetsList` reuses `MetricGrid` (extracted from `EvalSuitesList`).
- Chat modes: `chat.mode {spaceId, mode}` with `CHAT_MODES` = default/acceptEdits/plan/auto/dontAsk (never bypassPermissions); `chat.model {spaceId, model}` with `CHAT_MODELS` (`@pm/protocol` `lib/chat.ts`: claude-opus-5-5 default = `MASTER_MODEL`, claude-sonnet-5-5, claude-haiku-5-5, claude-fable-5-1; new sessions get `model: state.model`, live ones `setModel`; `chat.history`/`chat.status` carry `model`; web `ModelSelect` above Send, disabled until the server reported it; subagents stay forced to Sonnet); mode per-space in memory (default `auto`), survives reset/resume; new sessions get `permissionMode: state.mode`, live ones `setPermissionMode`; SDK `system` messages with `permissionMode` update it (after ExitPlanMode approval the CLI reports the previous mode). Plan mode writes its plan file to `~/.claude/plans/` without a prompt; `PermissionPrompt` renders `ExitPlanMode` `input.plan` as Markdown.
- Token: `security/token.ts` persists it in `$PM_HOME/token.json` (0600) and reuses it across restarts (dev rebuilds), rotating at startup after `PM_TOKEN_TTL_DAYS` (7); `PM_TOKEN` overrides.
- Chat session slot: `chat.send` claims the session slot synchronously (`state.opening`), and reset bumps `generation` to cancel a creation in flight. Sessions use `settingSources: ['project']` with the chosen permission mode (default `auto`); see the security caveat in the root CLAUDE.md.
- Server `{type:'error'}` WS messages carry `spaceId` when the failing client message had one.
- Tests that open real sockets use `app.listen({ port: 0 })` and the `ws` client (devDependency). `pnpm dev` cannot run twice at once (Nx serve lock), so run `node apps/server/dist/main.js` directly if another dev session is up.
- Versions (`versions/`, gated by `git`): the eval runner writes a sidecar `<out>/pm-meta.json` (`PmMeta`: commit, tree, dirty, branch, spaceId, startedAt; `versions/sidecar.ts`) before each CLI invocation, best effort (any failure = no sidecar, never fails the run; cancel before the process exists just stops the loop). Routes `GET …/versions?limit` (log + per-commit eval summary and delta of trendable commits), `…/versions/compare?from&to` (changed files, per-case deltas with `runId/arm/n` of the trace to open, SKILL.md description+body bytes), `…/versions/gate?from&to`. Refs are matched against `REF_RE` (no leading `-`) and resolved with `rev-parse --verify ^{commit}` to full shas before use. A run maps to a commit by sidecar (or same tree), else by `startedAt` vs `git log` (flagged approx). Gate rules (`logic.ts`; no data = `unknown`, never pass): no-regression (no case score lower), ctx-not-grown, holdout-pass; `partial`/`skippedPaid`/baseline-only runs are excluded from trends. Known limits: holdout = cases tagged `holdout` in the working-tree suite, not the suite at the compared commit; skills counted only under `skills/<name>/SKILL.md`; only the newest 500 commits are scanned (older runs show no commit); passing `--output-dir` to the real CLI when the directory already exists (sidecar pre-creates it) is unverified.
