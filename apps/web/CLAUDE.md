# CLAUDE.md (apps/web)

Web implementation notes, moved out of the root CLAUDE.md. Server details are in `apps/server/CLAUDE.md`; the web parts of chat, plans, evals, git, hooks, experiments and context are described inline in the server file bullets (Chat, Plans, Evals, Git, Experiments, Context) next to the server code they use.

- `apps/web`: React 19 + Vite, `react-router` (v7+ single package, not `react-router-dom`), react-query, Mantine 9 (`@mantine/core`/`hooks`; `postcss.config.cjs` with `postcss-preset-mantine`) and SCSS Modules (`*.module.scss`, `sass-embedded`; no `.css` files besides Mantine's own import in `main.tsx`). `src/app/app.tsx` (token gate, providers, routes), `api/{auth,http}.ts` (token capture from `?token=` into localStorage; `request()` adds Bearer, throws `ApiError`, clears token on 401), `api/ws.ts` (singleton WS client with 1 s reconnect, replays `subscribe`; `useSpaceEvents`), `features/folder/FolderPicker` (no manual absolute paths), `features/spaces/` (hooks, `SpacesPage`, Create/Open dialogs), `features/files/` (tree, Monaco `FileEditor`, `NewFileDialog`), `features/chat/` (`useChat`, `ChatPanel`, `MessageList` with react-markdown, rendering only the last `MAX_ITEMS` (300) events and folding consecutive tool calls/results into a collapsed summary block, `PermissionPrompt`), `pages/WorkspacePage.tsx` (header + `Dashboard`; handles `fs.changed`). Workspace is a widget dashboard (`features/dashboard/`: `layout.ts` pure state + `useDashboard(spaceId)`, `Dashboard.tsx` on `react-grid-layout` v2, `AddWidgetMenu`): widget types files, editor, evals, chat, plan, runs, hooks, skills, git and experiments (`experiments` = `features/experiments/`: start form (cost cap, focus, cases), list, stage stepper with stage traces in the shared `TraceDialog`, hypothesis/eval comparison/verdict/proposal, branch diff, Cancel/Merge/Discard; gated by `masterLoop` via `WIDGET_FEATURE`, not in the default layout; the single global `PermissionPrompt` lives in `ChatProvider`, not in `ChatPanel`, so permission requests, e.g. of experiment executors, show without a chat widget; `runs` = recorded chat runs from `GET …/runs` in `features/runs/`, opening the shared `TraceDialog`, refetched when chat turns idle, not in the default layout; `hooks` = events x sources matrix over `GET/PUT …/hooks` in `features/hooks/` with a cell editor modal that validates drafts with `validateGroup`, also not in the default layout; `skills` = block outline, edit, move, duplicate, extract to `references/` (numbered if taken, sub-file created before SKILL.md is saved) and lint of `skills/*/SKILL.md` in `features/skills/` ("New skill" creates `skills/<name>/SKILL.md` via the files POST, name checked like `lintSkill`), FileEditor-style draft with conflict banner, also not in the default layout), draggable/resizable with free placement (`getCompactor(null, true)`: no gravity to the top, overlap allowed; the dashboard scrolls), removable and re-addable, pinnable (`static`: no move/resize/remove). The layout is persisted per space in localStorage `pm.dashboard.<spaceId>`; do not import `react-resizable` CSS (RGL's own `css/styles.css` has the handle styles). `useChat(spaceId)` is called once in `ChatProvider` (`features/chat/ChatContext.tsx`, always mounted around `Dashboard`; `ChatPanel` and the plan widget read it via `useChatContext()`), so chat state survives removing the chat widget and only chat/plan widgets re-render on chat events; the `fs.changed` handler and `fs.watch` effect live in `pages/useWorkspaceWatch.ts`; eval-dir watching and `useEvalRuns` depend on the evals widget being present. Widgets are instances `{i, type, x, y, w, h, static?, file?}` (`i` = `files`, `editor-2`, ...; old stored layouts without `type` derive it from `i`), and any widget can be duplicated or added several times (`layout.ts` `duplicateItem`/`addItem`, new widgets and copies open at the top center (`y` 0, centered `x`), overlapping what is there, with `z` above all others; a pointer-down in a widget raises it via `raiseItem`/`Item.z`, persisted with the layout; a copy is never pinned). Per-instance state: an editor's open file is `Item.file` (no `?file=` param), expanded dirs live in `Workspace` keyed by files-instance id (copied on duplicate, cleared on reset; the single `fs.watch` is the union of all of them, all editors' files and the evals dirs), and a file opened from any files/evals widget goes to the active editor (last clicked, else the first; `pickEditor`; none = a new editor is added). Chat, plan and evals duplicates are extra views of the same server state (one agent session and one eval runner per space); only draft text, scroll and open/collapsed state are per instance, and an evals/chat view mounted late misses the `eval.history` already sent to an earlier subscriber. `vite.config.mts` proxies `/api` and `/ws` to `127.0.0.1:$PM_PORT` without `changeOrigin` (the server's Host guard needs `localhost`); the dev port comes from `PM_WEB_PORT`. Web deps (including `zod`) are listed in `apps/web/package.json`.
- The web `useSpaceEvents` is reference-counted per space; a hook mounted after another already subscribed does not get a fresh `chat.history`. Server `{type:'error'}` WS messages carry `spaceId` when the failing client message had one; `useSpaceEvents` routes them to that space. Web `send()` queues non-subscribe messages while the socket is not open and flushes them on connect.
- Theme: `MantineProvider defaultColorScheme="auto"` in `app/app.tsx`; `index.html` has an inline script (same logic as `ColorSchemeScript`, key `mantine-color-scheme-value`) to avoid a flash. `features/theme/ColorSchemeToggle` (SegmentedControl Auto/Light/Dark via `useMantineColorScheme`) sits in the spaces-page and workspace headers. Custom SCSS must use Mantine variables (`var(--mantine-color-default-border)`, `light-dark()`), no color literals; the preset's `@mixin dark/light/hover` cannot be used in SCSS, but `light-dark()` works, but `rem()` does NOT: Sass resolves it to its built-in `rem($a, $b)` modulo function ("2 arguments required, but only 1 was passed", in any position, also inside minmax()/calc()); use plain `px` values; Monaco follows `useComputedColorScheme`. Dialogs are Mantine `Modal` (inline per dialog, Enter submits the `<form>`). Web tests run in jsdom with `src/test-setup.ts` (matchMedia, ResizeObserver, scrollIntoView polyfills, wired via `setupFiles` in `vite.config.mts`); `App` includes its own `MantineProvider`.
- Editor: Monaco is loaded from the CDN by `@monaco-editor/react` (no bundling, no CSP); `monaco-editor` is installed only for its types. The editor compares the server content with the last accepted disk content to tell external changes from its own saves.
- Versions widget (`features/versions/`, type `versions`, gated by `git` via `WIDGET_FEATURE`, not in the default layout): score sparkline + commit list (click two commits; default last two), compare pane with Files (plain list: `GET git diff` only compares a path with the working tree, so no commit-vs-commit diff), Cases (deltas, `from`/`to` buttons open the shared `TraceModal` with the server-provided `runId/arm/n`) and Gate (rule verdicts and warnings) tabs.
- Graph widget (`features/graph/`, type `graph`, no feature gate, not in the default layout): client-only structure graph. `buildGraph` (pure) turns the plugin dir listing, SKILL.md/agent texts (at most 100 fetched), `GET …/hooks` entries, `.mcp.json` servers and `GET …/evals/suite` cases into nodes (manifest, skill, agent, command, hook, script/reference file, mcp, case) and edges (hook -> `${CLAUDE_PLUGIN_ROOT}` script, skill -> linked files/skills via protocol `bodyLinks`, agent -> frontmatter `skills:`, skill/agent -> its frontmatter hooks); unresolved links are dropped. `layoutGraph` = one column per node kind. `GraphView` (`@xyflow/react`, its CSS imported there) is `React.lazy`-loaded so the library stays out of the main chunk; clicking a node with a file calls the active-editor `select`. Watch paths go through `onWatch` like the skills widget; `fs.changed` of plugin paths invalidates the `['graph', spaceId]` query.
- Description optimizer UI: `features/skills/OptimizeDescription.tsx` (button next to "New skill", modal with max cost, iterations 1..5, live train/holdout counts from `useEvalSuite` + protocol `splitTriggerCases`, hint to tag cases `trigger`/`holdout`; posts `kind: 'description'` through `useRunExperiment`). `features/experiments/DescriptionResult.tsx` renders `kind: 'description'` experiments in `ExperimentDetail` (verdict badge, warning, candidate table, original vs best text; buttons "Accept (merge)"/"Reject (discard)"); `Stages` shows only propose/eval for that kind. Not checked in a browser.
- Evals UI settings (`features/evals/prefs.ts`): one module-level store per `pm.evals.<spaceId>.<widgetId>` in localStorage (zod, per-field fallback to defaults, `useSyncExternalStore`, memory-only when storage throws; `EvalsTab` gets the dashboard item id as `widgetId`, `EvalPrefsScope` sets it for everything below, `copyPrefs` runs on widget duplicate; each widget instance is independent). Persisted: view, open run page, "Last runs shown", visible columns per table kind, visible charts, expanded state by key (`useOpen`/`useOpens`: `suite:`, `target:`, `run:<id>:case:`, `inv:`), run-form values (never the scaffold consent). `DataTable` (`DataTable.tsx`) renders `Column` registries from `columns.tsx` (`runs`, `suiteCases`, `runCases`, `invocations`; metric columns and `MetricGrid` charts share `METRICS` in `metrics.ts`); the "Columns"/"Charts" menus (`PickMenu`) save the choice for all tables of that kind; a column with a `has` predicate is hidden by default unless a row has data, `off` = hidden by default.
