# CLAUDE.md (apps/web)

Web implementation notes, moved out of the root CLAUDE.md. Server details are in `apps/server/CLAUDE.md`; the web parts of chat, plans, evals, git, hooks, experiments and context are described inline in the server file bullets (Chat, Plans, Evals, Git, Experiments, Context) next to the server code they use.

- `apps/web`: React 19 + Vite, `react-router` (v7+ single package, not `react-router-dom`), react-query, Mantine 9 (`@mantine/core`/`hooks`; `postcss.config.cjs` with `postcss-preset-mantine`) and SCSS Modules (`*.module.scss`, `sass-embedded`; no `.css` files besides Mantine's own import in `main.tsx`). `src/app/app.tsx` (token gate, providers, routes), `api/{auth,http}.ts` (token capture from `?token=` into localStorage; `request()` adds Bearer, throws `ApiError`, clears token on 401), `api/ws.ts` (singleton WS client with 1 s reconnect, replays `subscribe`; `useSpaceEvents`), `features/folder/FolderPicker` (no manual absolute paths; dot directories are listed too), `features/spaces/` (hooks, `SpacesPage`, Create/Open dialogs), `features/files/` (tree, Monaco `FileEditor`, `NewFileDialog`), `features/chat/` (`useChat`, `ChatPanel`, `MessageList` with react-markdown, rendering only the last `MAX_ITEMS` (300) events and folding consecutive tool calls/results into a collapsed summary block whose calls are paired with their results by `toolUseId` and rendered with the trace `ToolCall` row (`shared/trace/TraceFlow.tsx`: kind colour, `describeTool` summary, details mounted only while open and rendered by `shared/trace/DetailView` over the pure `shared/trace/details.ts` `parseDetail`: JSON objects/arrays as nested key/value rows (levels below the first collapsed and unmounted, long or multi-line strings as blocks with real newlines), content-block arrays as their text plus a label per other block, JSON-encoded strings decoded, anything else (also a cut, unparsable preview) raw); subagent tool events (`parentToolUseId`) are taken out of the list (so `MAX_ITEMS` counts master events) and shown under their Agent/Task row as a "Subagent: N tool calls" block, collapsed and unmounted until opened (every event kept; more than `CHUNK_CALLS` (50) paired calls are split into chunks with a "calls 51–100 · Read×12, Bash×5" header, only the last chunk expanded, collapsed chunks unmounted; when a live subagent grows past a boundary the old last chunk collapses and the new one expands, except chunks the user toggled: `shared/trace/useFollowedOpen`, also used by the trace prompt groups), nested subagents recursively with a `seen` guard against parent cycles; an Agent/Task row links "Open run trace" = `RunTraceModal` (`shared/trace/RunTraceModal.tsx`; the chat renders it through `LiveRunTraceModal`, which passes `useChatLiveRun(runId)` as the `live` prop: while that session streams the trace is refetched on new chat events via `shared/trace/hooks.ts` `useLiveRefetch`/`useLiveRunTrace`, at most once per 2.5 s plus once when the turn goes idle; same query key, so data and the dialog's open groups/chunks/scroll stay; without `live` the modal is static) (also for rows of an earlier resumed session; a session never recorded as a run shows not found), `PermissionPrompt`), `pages/WorkspacePage.tsx` (+ `pages/widgets.tsx`, `pages/workspaceStore.ts`; header with a house icon button "Back to list" (inline SVG, no icon library; Tooltip + aria-label) + `Dashboard`; handles `fs.changed`). Workspace is a widget dashboard (`features/dashboard/`: `registry.ts` widget metadata, `layout.ts` pure state + `useDashboard(spaceId)`, `Dashboard.tsx` on `react-grid-layout` v2, `AddWidgetMenu`): widget types files, editor, evals, chat, plan, runs, hooks, skills, git and experiments (`experiments` = `features/experiments/`: start form (cost cap, focus, cases), list, stage stepper with stage traces in the shared `RunTraceModal`, hypothesis/eval comparison/verdict/proposal, branch diff, Cancel/Merge/Discard; gated by `masterLoop` via the widget registry (`feature`), not in the default layout; the single global `PermissionPrompt` lives in `ChatProvider`, not in `ChatPanel`, so permission requests, e.g. of experiment executors, show without a chat widget; `runs` = recorded chat runs from `GET …/runs` in `features/runs/` (started, duration with the end in a tooltip, turns, cost, models, Claude version, commit, resumed from), opening the shared `shared/trace` `RunTraceModal`, refetched when chat turns idle, not in the default layout; `hooks` = events x sources matrix over `GET/PUT …/hooks` in `features/hooks/` with a cell editor modal that validates drafts with `validateGroup`, also not in the default layout; `skills` = block outline, edit, move, duplicate, extract to `references/` (numbered if taken, sub-file created before SKILL.md is saved) and lint of `skills/*/SKILL.md` in `features/skills/` ("New skill" creates `skills/<name>/SKILL.md` via the files POST, name checked like `lintSkill`), FileEditor-style draft with conflict banner, also not in the default layout), draggable/resizable with free placement (`getCompactor(null, true)`: no gravity to the top, overlap allowed; the dashboard scrolls), removable and re-addable (`static` items stay immovable, see the header bullet). The layout is persisted per space in localStorage `pm.dashboard.<spaceId>`; do not import `react-resizable` CSS (RGL's own `css/styles.css` has the handle styles). `useChat(spaceId)` is called once in `ChatProvider` (`features/chat/ChatContext.tsx`, always mounted around `Dashboard`; consumers use the context hooks listed in the Chat state bullet), so chat state survives removing the chat widget and only chat/plan widgets re-render on chat events; the `fs.changed` handler and `fs.watch` effect live in `pages/useWorkspaceWatch.ts`; eval-dir watching and `useEvalRuns` depend on the evals widget being present. Widgets are instances `{i, type, x, y, w, h, static?, file?}` (`i` = `files`, `editor-2`, ...; old stored layouts without `type` derive it from `i`), and any widget can be duplicated or added several times (`layout.ts` `duplicateItem`/`addItem`, new widgets and copies open at the top center (`y` 0, centered `x`), overlapping what is there, with `z` above all others; a pointer-down in a widget raises it via `raiseItem`/`Item.z`, persisted with the layout; a copy is never pinned). Per-instance state: an editor's open file is `Item.file` (no `?file=` param), expanded dirs live in the workspace store (`pages/workspaceStore.ts`) keyed by files-instance id (copied on duplicate, cleared on reset; the single `fs.watch` is the union of all of them, all editors' files, the skills/graph watch paths (arrays) and the evals dirs), and a file opened from any files/evals widget goes to the active editor (last clicked, else the first; `pickEditor`; none = a new editor is added). Chat, plan and evals duplicates are extra views of the same server state (one agent session and one eval runner per space); only draft text, scroll and open/collapsed state are per instance, and an evals/chat view mounted late misses the `eval.history` already sent to an earlier subscriber. `vite.config.mts` proxies `/api` and `/ws` to `127.0.0.1:$PM_PORT` without `changeOrigin` (the server's Host guard needs `localhost`); the dev port comes from `PM_WEB_PORT`. Web deps (including `zod`) are listed in `apps/web/package.json`.
- The web `useSpaceEvents` is reference-counted per space; a hook mounted after another already subscribed does not get a fresh `chat.history`. Server `{type:'error'}` WS messages carry `spaceId` when the failing client message had one; `useSpaceEvents` routes them to that space. Web `send()` queues non-subscribe messages while the socket is not open and flushes them on connect.
- Theme: `MantineProvider defaultColorScheme="auto"` in `app/app.tsx`; `index.html` has an inline script (same logic as `ColorSchemeScript`, key `mantine-color-scheme-value`) to avoid a flash. `features/theme/ColorSchemeToggle` (SegmentedControl Auto/Light/Dark via `useMantineColorScheme`) sits in the spaces-page and workspace headers. Custom SCSS must use Mantine variables (`var(--mantine-color-default-border)`, `light-dark()`), no color literals; the preset's `@mixin dark/light/hover` cannot be used in SCSS, but `light-dark()` works, but `rem()` does NOT: Sass resolves it to its built-in `rem($a, $b)` modulo function ("2 arguments required, but only 1 was passed", in any position, also inside minmax()/calc()); use plain `px` values; Monaco follows `useComputedColorScheme`. Dialogs are Mantine `Modal` (inline per dialog, Enter submits the `<form>`). Web tests run in jsdom with `src/test-setup.ts` (matchMedia, ResizeObserver, scrollIntoView polyfills, wired via `setupFiles` in `vite.config.mts`); `App` includes its own `MantineProvider`.
- Editor: Monaco is loaded from the CDN by `@monaco-editor/react` (no bundling, no CSP); `monaco-editor` is installed only for its types. The editor compares the server content with the last accepted disk content to tell external changes from its own saves.
- Versions widget (`features/versions/`, type `versions`, gated by `git` via the widget registry, not in the default layout): score sparkline + commit list (click two commits; default last two), compare pane with Files (`shared/diff/FileDiffList`, shared with the experiment branch diff: status + path rows, a click opens the read-only `shared/diff/DiffView` of that file between the two commits from `GET …/versions/diff`, labels `[from7, to7]`), Cases (deltas, `from`/`to` buttons open the evals `TraceModal` with the server-provided `runId/arm/n`) and Gate (rule verdicts and warnings) tabs.
- Graph widget (`features/graph/`, type `graph`, no feature gate, not in the default layout): client-only structure graph. `buildGraph` (pure) turns the plugin dir listing, SKILL.md/agent texts (at most 100 fetched), `GET …/hooks` entries, `.mcp.json` servers and `GET …/evals/suite` cases into nodes (manifest, skill, agent, command, hook, script/reference file, mcp, case) and edges (hook -> `${CLAUDE_PLUGIN_ROOT}` script, skill -> linked files/skills via protocol `bodyLinks`, agent -> frontmatter `skills:`, skill/agent -> its frontmatter hooks); unresolved links are dropped. `layoutGraph` = one column per node kind. `GraphView` (`@xyflow/react`, its CSS imported there) is `React.lazy`-loaded so the library stays out of the main chunk; clicking a node with a file calls the active-editor `select`. Watch paths go through `onWatch` like the skills widget; `fs.changed` of plugin paths invalidates the `['graph', spaceId]` query.
- Description optimizer UI: `features/skills/OptimizeDescription.tsx` (button next to "New skill", modal with max cost, iterations 1..5, live train/holdout counts from `useEvalSuite` + protocol `splitTriggerCases`, hint to tag cases `trigger`/`holdout`; posts `kind: 'description'` through `useRunExperiment`). `features/experiments/DescriptionResult.tsx` renders `kind: 'description'` experiments in `ExperimentDetail` (verdict badge, warning, candidate table, original vs best text; buttons "Accept (merge)"/"Reject (discard)"); `Stages` shows only propose/eval for that kind. Not checked in a browser.
- Evals UI settings (`features/evals/prefs.ts`): one module-level store per `pm.evals.<spaceId>.<widgetId>` in localStorage (zod, per-field fallback to defaults, built on `shared/storage` `createPersistentStore`: `useSyncExternalStore`, memory-only when storage throws; `EvalsTab` gets the dashboard item id as `widgetId`, `EvalPrefsScope` sets it for everything below, `copyPrefs` runs on widget duplicate; each widget instance is independent). Persisted: view, open run page, "Last runs shown", visible columns per table kind, visible charts, expanded state by key (`useOpen`/`useOpens`: `suite:`, `target:`, `run:<id>:case:`, `inv:`), run-form values (never the scaffold consent). `EvalDataTable` (`evals/EvalDataTable.tsx`: the generic `shared/table/DataTable` with the column choice persisted per `kind` in the prefs) renders `Column` registries (`shared/table/types.ts`) from `columns.tsx` (`runs`, `suiteCases`, `runCases`, `invocations`, `compare` (EvalCompare), `compare-versions`, `compare-experiments` = `caseCompareColumns` over protocol `CaseCompare` rows, the one case comparison table of Versions, experiments and `EvalCompare`, each with its own saved columns (their registries differ: Traces only with `onTrace`, `EvalCompare`'s extra Changed graders) (from → to with Δ, optional trace buttons and `extra` columns); metric columns and `MetricGrid` charts share `METRICS` in `metrics.ts`); the "Columns"/"Charts" menus (`shared/table/PickMenu`) save the choice for all tables of that kind; a column with a `has` predicate is hidden by default unless a row has data, `off` = hidden by default.
- Chat window: `useChat` keeps `{events, earlier, conversation}`; `chat.event` appends and cuts to `chatWindowStart` like the server, `conversation` counts `chat.history` messages (MessageList scrolls to the end only when it changes). MessageList renders the same window, keys rows by absolute event index (`earlier` + position) and shows "N earlier events hidden · Open full trace". Running agents line: who (`name`/`subagentType`), task, action, tools and tokens; a click opens `SubagentTraceModal` (`shared/trace/RunTraceModal.tsx`, via the chat's `LiveSubagentTraceModal`): the run trace reduced by `shared/trace/subagent-trace.ts` `subagentTrace` to that Agent call's turns. Sessions switcher: a delete button per option (not the open one) with a confirm modal; the list refetches when a turn ends. `api/ws.ts`: one socket at a time (a stale socket's close/frames are ignored), reconnect backoff 1 s → 30 s, immediate reconnect on `visibilitychange`/`online`.
- Layers (`src/architecture.test.ts` enforces them; it reads the sources with `node:fs`, no dependencies):
  - `shared/` is generic and feature-agnostic and imports nothing from `features/`, `pages/` or `app/`: `shared/format` (all formatters: `cost`, `duration`/`seconds`/`clock`, `ago`, `shortHash`, `signed`/`delta`, `bytes`), `shared/table` (`DataTable`, `PickMenu`, `Column` types), `shared/diff` (`FileDiffList`, `DiffView`), `shared/storage` (below), `shared/ui` (`ErrorBoundary`, `useLatestCallback`, `QueryError`, `status.ts` colour maps, `useMonacoTheme`), `shared/trace` (the trace viewer: `TraceFlow`, `TraceView` (`TraceBody`/`TraceDialog`/`SubagentTraceBody`), `DetailView`, `details`, `describeTool`, `useFollowedOpen`, `subagent-trace`, `MetricChart`, plus `RunTraceModal`/`SubagentTraceModal` and the run-trace hooks `useRunTrace`/`useLiveRefetch`/`useLiveRunTrace`; modals get live info as the `live` prop `{tick, running}`, never from chat context).
  - A feature exposes a public `features/<x>/index.ts`; other features, `pages/` and `app/` import only `features/<x>` (never a deep path), a feature imports neither `pages/` nor `app/`, `api/` imports no feature, and there are no import cycles between features (the test reports the cycle path). Today: chat -> context, sound; evals -> context; experiments -> evals; files -> context; git, plans, runs, versions -> chat; graph -> evals, hooks, files; settings -> featureflags, sound, theme; skills -> files, evals, experiments; spaces -> folder, runs, theme; versions -> evals. Tests may mock deep paths (`vi.mock('../chat/ChatContext')`). New cross-feature need: add the export to the index of the feature that owns it, or move generic code to `shared/`.
  - Domain-specific evals pieces stay in `evals` and go out through its index (`EvalDataTable`, `caseCompareColumns`, `SuiteVerdict`, `TraceModal`, `TrustCheckbox`/`ScaffoldCheckbox`, `useEvalSuite`, ...).
- `shared/storage`: `storage` (`get`/`tryGet`/`set`/`remove`, never throws), `usePersistentFlag(key, fallback)` ("1"/"0"), `createPersistentStore` (module-level store per scope for `useSyncExternalStore`, memory-only while storage is unavailable; used by `evals/prefs.ts` and `sound/sounds.ts`). Keys are unchanged (`pm-token`, `pm.chat.controlsOpen`, `pm.files.plainEditor`, `pm.sound`, `pm.dashboard.<id>[.layouts]`, `pm.evals.<scope>`); never touch `localStorage` directly.
- Shared helpers to reuse: `files` exports `listDir`/`listDirIfExists`/`walkFiles`/`readFileText` (the one tree walk, used by skills and graph) and `useSaveDraft` (save -> `draft.saved` -> `setQueryData`, used by `FileEditor` and `SkillEditor`); `skills/paths.ts` `skillPath(name)`/`skillDir(name)`; `evals/CollapsibleSection` (the suite/target block); `FEATURE_REQUIRES`/`featureDependents` in protocol drive `FeaturesMenu` (git off also turns off autoCommit/masterLoop).
- Widget registry: `features/dashboard/registry.ts` `WIDGETS` holds per type `{title, feature?, defaultSize}` (titles, add menu order, feature gate `widgetEnabled`, default sizes of `addItem`/`DEFAULT_ITEMS`); `pages/widgets.tsx` `WIDGET_REGISTRY` adds the `Component` per type (exhaustive over `WidgetType`) and `renderWidget`. A new widget type = one entry in each. `useDashboard` returns stable actions (`useLatestCallback` where they need the current items), so `render` in `WorkspacePage` depends only on the space id. Workspace state that widgets read lives in `pages/workspaceStore.ts` (expanded dirs per files instance, active editor, skills/graph watch paths as arrays; selector hooks `useExpandedDirs`, `useSelectedFile`, `useWatchPaths`; `WorkspaceApi` has `select`, `setFile`, `toggleDir`, `setWatch`, `openNewFile` and never changes identity): a folder toggle re-renders only the files widgets, a selection only trees and editors (`WorkspacePage.rerender.test.tsx` counts renders of mocked chat/evals/plan widgets).
- Chat state is a pure reducer (`chat/reducer.ts`) feeding five contexts (status, settings, log, stats, actions). Consumers use `useChatStatus`, `useChatSettings`, `useChatLog`, `useChatStats`, `useChatActions`, `useChatLiveRun` and should never subscribe to more than they render; `useOnChatIdle` is status-only. Message grouping lives in `chat/toolRows.ts`, and `MessageList` needs a `conversation` prop: it follows new events only within 24 px of the bottom, and a `conversation` change jumps to the end.
- Every widget body is wrapped in `shared/ui/ErrorBoundary` with a "Reload widget" fallback, plus a top-level boundary in `WorkspacePage`.
- The dashboard is responsive: lg >=1280 -> 12 cols, md >=900 -> 8, sm -> 4. lg (`pm.dashboard.<id>`) is the source of truth; md/sm hold only changed rects in `pm.dashboard.<id>.layouts` (`parseBpLayouts`), the rest come from `layoutFor`/`deriveRect`. Placement is free everywhere, with no extra space after the last widget. On coarse pointers the resize handle is 32 px and sticks out 20 px to the right of the tile (`.widget` does not clip, `.body` does; the dashboard hides horizontal overflow), so it does not cover bottom-right controls such as the chat Send/Stop.
- The widget header has Maximize (no pinning: a stored `static` flag is dropped by `parseItems`, every widget can be moved, resized and removed): a Modal (`fullScreen` on small screens) that does NOT remount the widget. `HostedBody` renders each body through a portal into its own DOM node; only that node moves between the tile slot and the dialog body (`place`: `Element.moveBefore` when both nodes are in the document, which keeps scroll, focus and iframes, else `appendChild`), so React state survives in every browser; the node (`.host`) is the scroll container, the tile shows "Shown maximized". The header has the "▤" `WidgetsMenu` (raise, expand, activate the editor; `revealWidget` scrolls `[data-widget]` into view), the `FeaturesMenu` and the "⚙" `SettingsMenu` dropdown (`sound` `SoundMenuItems`: finish sound + volume, and the color scheme).
- Data layer: `api/space.ts` `spaceUrl()` encodes path segments and `useSpaceInvalidate` replaces per-hook WS -> invalidate code; every data-returning `request()` has a zod schema (the git/versions/experiments schemas are in protocol); WS frames are validated cheaply and invalid ones are dropped with a warning; the QueryClient uses `staleTime` 30 s, `refetchOnWindowFocus: false` and `staleTime` 0 for queries without push (spaces list, folder browser); there is a catch-all "Not found" route; "Remove from list" asks for confirmation.
- Evals extras: `prefs` has a per-key `useOpen` selector; `runRequest.ts` `buildRunRequest`; `compare.ts` `latestPerCase`/`repeatedCaseNames` plus a `Baseline` union instead of sentinel strings.
